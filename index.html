Kapitola 1 / 7 · Základy

Co je PHP a jak funguje

PHP je skriptovací jazyk, který běží na serveru. Prohlížeč nikdy nedostane PHP kód, dostane jen jeho výsledek, typicky HTML.

Cesta jednoho požadavku

1 · PROHLÍŽEČuživatel otevře http://localhost/index.php a odešle HTTP požadavek GET
2 · WEBOVÝ SERVERApache nebo Nginx podle přípony .php pozná, že soubor nemá poslat, ale nechat zpracovat
3 · INTERPRET PHPpřeloží skript na bytecode, spustí ho, případně se dotáže databáze
4 · DATABÁZE (volitelně)MySQL / MariaDB, PostgreSQL, SQLite
5 · ODPOVĚĎserver pošle prohlížeči vygenerované HTML; PHP kód zůstává na serveru

Kód × co vidí prohlížeč

index.php na serveru

<!doctype html>
<p>Dnes je <?= date('j. n. Y') ?></p>
<?php
  $zaci = ['Anna', 'Jan', 'Petra'];
  echo '<p>Ve třídě je ' . count($zaci) . ' žáků.</p>';
?>

Zdrojový kód stránky v prohlížeči

<!doctype html>
<p>Dnes je 1. 10. 2026</p>
<p>Ve třídě je 3 žáků.</p>

<?php … ?> ohraničuje PHP kód, <?= … ?> je zkratka pro echo.

Kapitola 2 / 7 · Instalace

Samostatná instalace PHP

Samotný interpret stačí pro skripty v terminálu a pro vestavěný webový server. Webový server a databázi lze doinstalovat později.

Windows — ZIP archiv

  1. Stáhnout z windows.php.net/download verzi x64, archiv ZIP.
  2. Vybrat Thread Safe (pro Apache s mod_php) nebo Non Thread Safe (CLI, FastCGI, IIS). Pro výuku CLI stačí NTS.
  3. Rozbalit do C:\php. Bez mezer a diakritiky v cestě.
  4. Zkopírovat php.ini-development jako php.ini.
  5. Přidat C:\php do proměnné Path: Nastavení → Systém → O systému → Upřesnit nastavení systému → Proměnné prostředí.
  6. Otevřít nový terminál a ověřit php -v.
Když php.exe hlásí chybějící VCRUNTIME140.dll, doinstalujte Microsoft Visual C++ Redistributable (x64) pro Visual Studio 2015–2022.

Ověření ve Windows

PS> php -v
PHP 8.4.13 (cli) (built: …) (NTS Visual C++ 2022 x64)
Copyright (c) The PHP Group
Zend Engine v4.4.13

PS> where.exe php
C:\php\php.exe

PS> php --ini
Loaded Configuration File: C:\php\php.ini

Čísla verzí jsou ilustrativní. Pokud php --ini ukáže (none), PHP nenašlo php.ini a běží s výchozími hodnotami.

Alternativa

WSL s Debianem: instalace je pak stejná jako v Linuxu (vedle).

Debian / Ubuntu — apt

$ sudo apt update
$ sudo apt install php-cli          # jen interpret pro terminál
$ php -v
PHP 8.4.x (cli) …              # Debian 13 obsahuje PHP 8.4

$ sudo apt install php-mysql php-mbstring php-xml php-curl
                                    # běžná rozšíření (kapitola 5)
$ apt list --installed 'php*'       # co je nainstalováno
Pozor: balíček php (bez přípony) doinstaluje i Apache s mod_php. Na server s Nginx proto instalujte php-fpm, ne php.

Novější verze než v distribuci

Repozitář packages.sury.org udržuje Ondřej Surý, správce PHP balíčků v Debianu. Nabízí všechny podporované větve a umožňuje mít jich nainstalováno víc najednou (php8.3-cli, php8.5-cli, přepnutí přes update-alternatives --config php).

macOS a Docker

macOS — Homebrew

$ brew install php
$ php -v
$ brew services start php     # PHP-FPM jako služba

Docker — oficiální obrazy

# interaktivní PHP bez instalace
$ docker run --rm -it php:8.5-cli php -a

# spustit skript z aktuální složky
$ docker run --rm -v "$PWD":/app -w /app php:8.4-cli php skript.php

# Apache + PHP na portu 8080
$ docker run --rm -p 8080:80 -v "$PWD":/var/www/html php:8.4-apache

Výhoda: přesná verze, stejné prostředí u všech žáků i na serveru.

XAMPP — instalace a spuštění

  1. Stáhnout instalátor z apachefriends.org.
  2. Instalovat do C:\xampp, ne do C:\Program Files (kvůli oprávněním UAC).
  3. Spustit XAMPP Control Panel a tlačítkem Start zapnout Apache a MySQL.
  4. Otevřít http://localhost/ (úvodní stránka) a http://localhost/phpmyadmin/.
  5. Vlastní soubory ukládat do C:\xampp\htdocs\, např. htdocs\test\index.php → http://localhost/test/.

Docker Compose místo XAMPP

Soubor compose.yaml v kořeni projektu popisuje celé prostředí. Spuštění: docker compose up -d.

services:
  web:
    image: php:8.4-apache
    ports: ["8080:80"]
    volumes: ["./src:/var/www/html"]
  db:
    image: mariadb:11
    environment:
      MARIADB_ROOT_PASSWORD: heslo
      MARIADB_DATABASE: skola
  pma:
    image: phpmyadmin
    ports: ["8081:80"]
    environment: { PMA_HOST: db }
Jen pro vývoj. Balíčky typu XAMPP mají výchozí účet root v databázi bez hesla, zapnuté zobrazování chyb a vypnutá bezpečnostní omezení. Na veřejný server patří samostatně nainstalovaný a nastavený Apache/Nginx, PHP a databáze.

Konfigurační soubory

Chování PHP řídí soubor php.ini: limity paměti a času, velikost nahrávaných souborů, zobrazování chyb i načtená rozšíření. Nejdřív je třeba zjistit, který soubor se opravdu načítá.

Který php.ini se načítá?

$ php --ini
Configuration File (php.ini) Path: /etc/php/8.4/cli
Loaded Configuration File:         /etc/php/8.4/cli/php.ini
Scan for additional .ini files in: /etc/php/8.4/cli/conf.d
Additional .ini files parsed:      /etc/php/8.4/cli/conf.d/10-opcache.ini,
                                   /etc/php/8.4/cli/conf.d/20-mbstring.ini, …

Pro web vytvoříme dočasný soubor a hledáme řádek Loaded Configuration File:

<?php phpinfo();
phpinfo() prozradí útočníkovi vše o serveru. Po použití soubor smažte.

Kde soubory leží

ProstředíSoubor

V Debianu má každé SAPI vlastní php.ini. Změna v cli/php.ini se na webu neprojeví a naopak.

Syntaxe

[Session]                    ; sekce jsou jen pro přehlednost
session.gc_maxlifetime = 1440

Šablony

PHP přichází se dvěma vzory: php.ini-development (chyby zobrazuje) a php.ini-production (chyby jen loguje, přísnější). Na vlastním počítači použijte první, na serveru druhý.

Zapnutí ve Windows / XAMPP

Rozšíření jsou soubory php_*.dll ve složce ext. Zapínají se odkomentováním řádku v php.ini:

; kde hledat .dll soubory
extension_dir = "ext"

; běžná rozšíření — smazat středník na začátku
extension=curl
extension=gd
extension=intl
extension=mbstring
extension=mysqli
extension=openssl
extension=pdo_mysql
;extension=pdo_pgsql        ; zůstává vypnuté

; rozšíření jádra Zend
zend_extension=opcache
Po úpravě restartovat Apache (XAMPP Control Panel → Stop / Start). Hláška Unable to load dynamic library znamená špatnou cestu extension_dir nebo .dll pro jinou verzi PHP.

Zapnutí v Debianu

# nainstalovat (zapne se automaticky)
$ sudo apt install php8.4-mysql php8.4-gd php8.4-intl

# ručně vypnout / zapnout
$ sudo phpdismod xdebug
$ sudo phpenmod xdebug
$ sudo phpenmod -s cli xdebug          # jen pro CLI

# projevit na webu
$ sudo systemctl restart apache2       # nebo php8.4-fpm

$ ls -l /etc/php/8.4/apache2/conf.d/
20-gd.ini -> /etc/php/8.4/mods-available/gd.ini
20-mysqli.ini -> /etc/php/8.4/mods-available/mysqli.ini …

Číslo na začátku názvu (10-, 20-) určuje pořadí načítání.

Xdebug — ladění v editoru

Xdebug umí zastavit skript na zarážce (breakpoint) ve VS Code nebo PhpStormu a ukázat hodnoty proměnných. Ve VS Code k tomu slouží rozšíření PHP Debug.

; /etc/php/8.4/mods-available/xdebug.ini  (nebo php.ini)
zend_extension=xdebug
xdebug.mode = debug,develop
xdebug.start_with_request = yes
xdebug.client_port = 9003
Xdebug výrazně zpomaluje běh. Na produkčním serveru ho nezapínejte.

Rozšíření mimo distribuci

PECL a PIE

Rozšíření, která nejsou v balíčcích, lze přeložit ze zdrojového kódu. Starší nástroj je pecl, novější pie (PHP Installer for Extensions). V Debianu je pohodlnější hledat nejdřív balíček php-….

$ sudo apt install php8.4-dev       # hlavičky pro překlad
$ sudo pecl install redis
$ echo "extension=redis" | sudo tee /etc/php/8.4/mods-available/redis.ini
$ sudo phpenmod redis

Docker

RUN docker-php-ext-install pdo_mysql intl

PHP přes HTTP server

Aby PHP generovalo webové stránky, musí ho volat webový server. Ukážeme tři způsoby: vestavěný server pro vývoj, Apache s modulem PHP a Nginx s PHP-FPM.

Vestavěný server

php -S adresa:port [-t kořen] [router.php]
$ cd ~/projekt
$ php -S localhost:8000
[Thu Oct  1 10:15:02 2026] PHP 8.4.13 Development Server (http://localhost:8000) started

$ php -S localhost:8000 -t public/     # kořen webu ve složce public
$ php -S 0.0.0.0:8000                  # dostupné i z jiných PC v síti
$ php -S localhost:8000 router.php     # všechny požadavky přes router
Ideální do výuky: žádný Apache, žádný XAMPP, stačí php v PATH. Ukončení Ctrl+C.
Nikdy ne na produkci: je jednovláknový a nemá bezpečnostní nastavení.

Apache + mod_php (Debian)

$ sudo apt install apache2 libapache2-mod-php php-mysql
$ systemctl status apache2

# kořen webu
$ ls /var/www/html
$ echo '<?php phpinfo();' | sudo tee /var/www/html/info.php
# → http://IP-serveru/info.php, pak soubor smazat

# vlastní soubory: vlastník www-data, nebo skupina
$ sudo chown -R www-data:www-data /var/www/html

# povolit .htaccess s mod_rewrite
$ sudo a2enmod rewrite
$ sudo systemctl restart apache2

Pro .htaccess musí být v konfiguraci webu AllowOverride All. XAMPP i WampServer fungují stejným modelem.

Nginx + PHP-FPM (Debian)

$ sudo apt install nginx php8.4-fpm
$ systemctl status php8.4-fpm

/etc/nginx/sites-available/default

server {
    listen 80;
    root /var/www/html;
    index index.php index.html;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
    }
}
$ sudo nginx -t && sudo systemctl reload nginx

Apache umí FPM také: a2enmod proxy_fcgi a a2enconf php8.4-fpm.
